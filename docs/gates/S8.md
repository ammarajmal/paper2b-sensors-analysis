Stage: S8 (number ledger and manuscript number check)   Date written: 2026-10-17 (BEFORE the ledger is built)
Purpose: every number the manuscripts take from the rebuild comes from one table (results/ledger.csv) with its provenance, and every number printed in a manuscript can be checked against it.
Ledger rows (scripts/build_ledger.py): id, group, description, value, unit, population/session, source_file, source_key (column and selector), producing script, git commit of the repository at build time, sha256 of the source file. Content: reference frequencies, timing census, detection counts, spectra peaks, laser session statistics, S6 headline metrics (rules a, b, d; arms A, B; primary quantities), S6b labelled exploratory, S7 medians and coverage, open-issue checks. Rows from exploratory variants carry group prefix EXPL_. No number enters the ledger by hand; each is read from a results file by a stated key.
Checker (scripts/check_number_ledger.py), two parts:
 (1) Curated claims: a hand-written file results/claims_map.csv links named manuscript claims (register rows R001-R005, frequencies, timing facts, counts) to a ledger id and the printed value; the checker reports AGREE (equal at the printed precision), DIFFER (with both values) or NOT_IN_LEDGER.
 (2) Full scan: every numeric token in the two manuscripts (Sensors main .tex, Measurement sections .tex) is listed with file, line and context and flagged VALUE_IN_LEDGER (equal at the printed precision to some ledger value; this is a value coincidence, NOT proof that it is the same quantity) or NO_LEDGER_VALUE. Counts are reported per file.
Pass criteria (about the machinery, not about the manuscripts):
 P1 every ledger row has all fields filled; the source value is re-read independently by the checker and equals the ledger value (tolerance 0);
 P2 building the ledger twice gives byte-identical files;
 P3 the checker runs to completion on both manuscripts and writes results/number_check_report.csv and results/number_check_summary.md;
 P4 no ledger value is computed from a manuscript;
 P5 curated claims cover at least R001-R005 and the reference frequencies, each with a status.
Not a criterion: that manuscript numbers agree with the ledger. DIFFER and NO_LEDGER_VALUE are findings for the owner; the manuscripts are not edited in this stage.

ADDENDUM S8b (2026-10-17, written BEFORE the extension is built): per-RPM tables and intervals (owner decision 2: widen the claims map). Owner decision 1 (rebuilt numbers carried throughout) is in DECISIONS.md.
Tables covered: Measurement tab:bending (per-RPM cam/LDS RMS and peak, ratios), tab:supp_s2 (2024 LDS, 2025 LDS, camera, bending and torsion RMS), tab:torsion, tab:robustness (LOO range, log-scale r, regression slope and CI); Sensors tab:tb4-posthoc-reference (dominant frequencies, laser and cameras), tab:rpm-sweep (per-stream dominant feature and Rayleigh resolution), the cam1/cam2 same-marker agreement table, tab:timebase. Mechanism: a LaTeX table parser reads every row whose first cell is an integer RPM (or a condition name with RPM); a hand-written results/table_map.csv assigns each column to a ledger id template ({rpm}, {cond}, {cam}) or to a derived expression of two ledger ids (ratio a/b, difference); no value is taken from the manuscript into the ledger. Every cell is reported AGREE (equal at its printed precision), DIFFER (both values and the relative difference) or UNMAPPED (column not in the map, with the reason). Peak definition for camera series follows the laser convention (max |x - mean|), stated in the map.
New ledger content: (a) per-RPM rows from s6_matched_pairs (camera legacy bending and torsion RMS, line amplitudes, camera dominant frequency) and the laser peak columns; (b) camera legacy-series peaks, which the pipeline did not compute: added to compare.camera_table as two additive columns; S6 is re-run and the gate requires that every pre-existing S6, S6b and S7 ledger row is unchanged (regression guard); (c) S3 columns f_E0, T, RI per stream and the timebase shifts; (d) intervals: percentile bootstrap over the 16 conditions of the manuscripts' set (2,000 resamples, seed 11) for Pearson r, Spearman rho, mean ratio, MAE, RMSE and the OLS slope (cam = slope x LDS + intercept, with intercept), leave-one-out range of r, and the Pearson r of the log RMS values, for bending and torsion proxy. The manuscripts do not state their bootstrap method; the method used here is stated in the ledger description and equality of intervals is not expected.
Pass criteria: S1 the parser finds the expected number of data rows in each covered table (19 or 20 or 21 as the table's own caption states) and every cell is classified; S2 every id in table_map.csv exists in the ledger; S3 the ledger rows added before this addendum are byte-identical in value after the S6 re-run (checked row by row); S4 two builds are byte-identical; S5 the independent recompute (P1) still gives 0 differences over all rows including the new ones.
Not a criterion: agreement of printed and rebuilt values; every DIFFER is a finding for the paper revision (decision N: the rebuilt value is carried).
